# 알고리즘 배포와 실행 환경 검증

[포트폴리오](../README.md) · [평가 사례](02-evaluation.md)

> **English summary:** Worked on algorithm verification across Python and native execution. The project identified deployment artifacts and compared detection outcomes and timing, keeping recorded-data replay separate from device-level validation.

**핵심 사례** · 5,912개 저장 시행의 실행 경로 비교에서 판정 일치와 검출 시점 차이를 구분했습니다. 호스트 재생 검증 사례입니다.

## 1. 프로젝트와 담당 업무

- **대상:** 웨어러블 낙상 감지 알고리즘의 제품 적용.
- **담당:** 알고리즘 개발·평가·개선과 관련 실행 결과 검토.
- **프로젝트 구성:** Python 평가, TensorFlow Lite 모델, C/C++ 네이티브 알고리즘, Windows DLL, ARM 대상 라이브러리.

## 2. 해결해야 했던 문제

연구 환경의 판정과 제품 적용용 실행을 비교하려면 같은 입력과 모델을 사용했는지부터 확인해야 합니다. 버전 이름이 같더라도 모델 파일, 모델 호출 조건, 전처리 또는 파생 데이터 생성 시점이 다르면 결과가 달라질 수 있습니다.

## 3. 검증 접근

1. 학습 체크포인트와 추론용 모델을 구분하고 파일 해시로 모델을 식별했습니다.
2. 보관된 배포 모델과 펌웨어 소스에 포함된 모델 바이트의 일치 여부를 확인하는 경로를 다뤘습니다.
3. 같은 파생 입력을 사용하는 Python·네이티브 비교와, 원본 입력을 사용하는 DLL 비교를 나눴습니다.
4. 판정 결과뿐 아니라 첫 검출 시점의 차이를 확인했습니다.

## 4. 기록된 동작 비교

2026-09-29 알고리즘 1.3.5 조사 기록의 표준 9개 데이터 세트, 총 **5,912개 저장 시행**에 대한 비교입니다. KFall과 추가 낙상·일상동작 세트를 포함하는 개발·회귀 검증 자료입니다.

| 실행 경로 | 비교 항목 | 기록된 일치 수 |
|---|---|---:|
| 현재 DLL이 생성한 파생 입력의 Python ↔ 네이티브 재생 | 첫 검출 프레임과 판정 모드 | 5,912 / 5,912 |
| 원본 센서 CSV의 DLL 실행 ↔ 파생 입력의 네이티브 재생 | 판정과 모드 | 5,912 / 5,912 |
| 원본 센서 CSV의 DLL 실행 ↔ 파생 입력의 네이티브 재생 | 첫 검출 프레임 | 5,911 / 5,912 |

**위 수치는 실행 결과의 일치도이며 낙상 검출률이 아닙니다.** 시점이 다른 1건은 파생 데이터에 기록되는 모델 점수의 반올림 경계와 일치하는 현상으로 조사됐습니다. 두 실행 경로가 모든 프레임에서 완전히 같다고 표현하지 않았습니다.

## 5. 제품 적용 관점의 결과

- 배포 모델의 식별과 평가 경로 비교를 연결했습니다.
- 실행 결과 차이를 입력·모델·판정·출력 정밀도로 나누어 추적했습니다.
- 프로젝트에는 Windows DLL 및 ARM 대상 빌드 검증 기록이 있습니다. 이 사례의 수치는 호스트 재생 비교이며 실제 보드의 처리시간이나 최종 알람 성능을 측정한 값은 아닙니다.

이 경험을 통해 알고리즘 개발 결과를 제품 적용용 검증으로 이어가는 관점을 쌓았습니다.
