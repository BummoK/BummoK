# 미검출로 보였던 2건의 원인을 찾다

[포트폴리오](../README.md) · [알고리즘 개발](01-sensor-ai.md) · [실행 결과 비교](03-deployment-verification.md)

새 알고리즘을 평가하던 중 일부 낙상이 검출되지 않는 결과가 나왔습니다. 센서 원본부터 다시 따라가 보니, **이전 DLL에서 생성한 모델 출력이 새 판정의 입력으로 사용되고 있었습니다.**

## 1. 무엇부터 확인했나

| 질문 | 확인한 내용 |
|---|---|
| 원본 동작은 같은가? | 센서 파일과 시간축 |
| 같은 모델을 사용했나? | 모델 파일과 출력 생성 버전 |
| 같은 경로로 실행했나? | 원본 CSV의 DLL 실행과 파생 데이터 재생 |
| 결과가 어디서 달라지나? | 판정 모드와 첫 검출 프레임 |

## 2. 조사 과정

1. 원본 센서 데이터와 평가용 파생 데이터, 모델 출력을 대조했습니다.
2. 파생 데이터의 출력이 과거 DLL에서 생성된 사실을 확인했습니다.
3. 현재 DLL로 원본을 다시 실행하고 입력 버전을 맞췄습니다.
4. 미검출로 표시됐던 **2건의 검출을 재현**했습니다.

알고리즘을 바꾸기 전에 평가 입력부터 바로잡아야 했던 사례입니다. 이후 비교에서는 검출 여부가 같아도 첫 검출 시점이 한 프레임 다른 경우가 있어, 시점까지 별도로 확인했습니다.

## 3. 평가 방식에 반영한 것

평가 결과에 입력 파일, 모델과 판정 버전, 첫 검출 시점을 함께 남깁니다. 실패로 표시된 사례는 원본 동작으로 돌아가 확인하고, 같은 데이터와 실행 조건으로 수정 전후를 비교합니다.

*2026-09-29, 알고리즘 1.3.5의 저장 데이터 재생 조사 사례입니다.*

**기술:** Python · NumPy · pandas · DLL 재생 · 신호·판정 타임라인 분석
