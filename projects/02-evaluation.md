# 시행 단위 평가와 오류 원인 분석

[포트폴리오](../README.md) · [개발 사례](01-sensor-ai.md) · [배포 검증 사례](03-deployment-verification.md)

> **English summary:** Evaluated fall-detection algorithms at the trial level and investigated discrepancies across replay paths. A recorded investigation traced two apparent missed detections to outdated model-score inputs generated by an older DLL version.

**핵심 사례** · 미검출로 표시된 2건에서 과거 모델 출력이 재생 입력에 사용된 원인을 추적했습니다. 평가 입력의 정정 사례입니다.

## 1. 프로젝트와 담당 업무

- **대상:** 낙상 감지 알고리즘의 평가·개선 업무.
- **담당:** 성능 평가, 실패 사례 분석, 개선안의 영향 검토.
- **기술 환경:** Python, NumPy/pandas, 파일별 평가, 신호·판정 타임라인, 네이티브 재생 비교.

## 2. 평가 설계

| 확인할 질문 | 평가 방법 |
|---|---|
| 낙상을 놓치는가 | 원본 시행별 검출·미검출 확인 |
| 일상동작에 반응하는가 | 정상 동작 시행의 오검출 확인 |
| 충분히 일찍 검출하는가 | 지정된 접촉 기준과 첫 검출 시점 비교 |
| 특정 조건에 취약한가 | 동작·착용 조건별 실패 사례 분리 |
| 개선 후 기존 동작이 달라지는가 | 같은 파일과 평가 경로를 사용하는 회귀 비교 |

파일별 판정 결과와 검출 시점, 입력·알고리즘 버전을 함께 남겨 결과를 다시 추적할 수 있도록 했습니다.

## 3. 대표 문제 해결 사례

**문제:** 새 알고리즘 평가에서 일부 낙상이 미검출로 표시됐습니다.

1. 원본 센서 데이터, 평가용 파생 데이터, 모델 출력, 판정 구현을 나누어 대조했습니다.
2. 과거 DLL에서 생성한 모델 출력이 현재 판정의 재생 입력에 사용된 경로를 확인했습니다.
3. 현재 DLL로 원본을 다시 재생하고 입력 버전을 맞추자 문제 사례의 검출이 재현됐습니다.
4. 후속 비교에서 원본 DLL 실행과 파생 데이터 재생의 검출 시점이 한 프레임 다른 사례도 별도로 남겼습니다.

기록된 조사에서는 미검출로 표시됐던 **2건**의 원인을 오래된 모델 출력 입력으로 설명했습니다. 해당 정정은 평가 입력 경로를 바로잡은 결과이며, 모델 자체의 검출 성능이 향상됐다는 의미로 사용하지 않았습니다.

## 4. 결과와 해석

- 알고리즘의 실패와 평가 입력·버전 불일치를 구분했습니다.
- 검출 여부, 판정 모드, 첫 검출 프레임을 각각 대조했습니다.
- 서로 다른 코호트나 실행 경로의 결과를 하나의 성능 개선 수치로 합치지 않았습니다.

2026-09-29 알고리즘 1.3.5 조사 기록을 바탕으로 한 저장 데이터 분석 사례입니다. 입력 생성 방식과 출력 정밀도가 달라지면 시점 차이가 생길 수 있어, 판정 일치와 시점 일치를 별도로 확인했습니다.
